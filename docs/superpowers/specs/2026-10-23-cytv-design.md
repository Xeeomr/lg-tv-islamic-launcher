# cytv standalone installer

Current edition wording (2026-10-24): No-root and Root are equal options for LG Developer Mode and existing root SSH environments. Historical “Root Preview” naming and edition recommendations below are superseded; recorded hardware-validation limits still apply.

Approved direction: one executable per desktop OS, one interactive installation wizard for No-root and Root Preview. Users need no Git, Node.js, Python, Bash, compiler or external SSH client. The executable embeds public launcher sources, compiled ARM32 helper and complete verified Root recovery bundle. It never embeds developer state, app inventory or credentials.

Python 3.11+ is the build runtime, with Paramiko for SSH, websockets for SSAP and PyInstaller for native executables. Windows x64, Linux x64, macOS ARM64 and macOS x64 build separately. Tests and source execution remain possible without freezing. Existing developer scripts remain available.

`cytv` and `cytv install` run the wizard. `status`, `doctor`, `restore` and `uninstall` reuse a local per-TV profile. Explicit `--host`, `--edition`, `--port`, `--identity` and `--data-dir` select a connection. Only first connection trust and actual TV pairing require interaction. Host keys are pinned; changed keys fail. A first-use confirmation on a trusted home network establishes a new pin; existing keys are checked automatically. Fingerprint comparison is optional detail. Credentials are private local files, never printed or passed in command arguments. No subnet/port scans or root exploitation.

User addition: find new TVs automatically using LG webOS SSDP on active local IPv4 interfaces (psutil inventory), bounded to three seconds plus a shared two-second name lookup budget. Present name/model/address with numbered selection, retry and manual fallback with IP help. Explicit host, saved profile reuse, noninteractive mode and `--no-discovery` skip the search. Parse only matching local replies; descriptions must use HTTP on the exact responding IP, with no proxies/redirects, bounded bytes/time and terminal-safe XML labels. Discovery never pairs or changes the TV and does not establish SSH trust. A blocked or empty search is a normal manual-fallback case; unexpected failures use issue diagnostics. No extra user-installed runtime is required.

User additions (0.1.3): improve terminal hierarchy and replace installer-facing "Root Preview" with "Root", retaining preview/compatibility information in the requirements. Use whitespace, bold default foreground, short questions and contextual help, with plain output when redirected. Start major steps on a fresh viewport in ANSI terminals without clearing scrollback. After a new TV address, read bounded SSH banners on Root/custom and Developer Mode ports to set the current edition choice for the detected connection. No login/commands/password guesses during detection. No-root and Root have equal standing; the user chooses based on LG Developer Mode or existing root SSH. An SSH banner is a connection hint, not proof of root; missing SSH is inconclusive. Final authenticated Root preflight still checks uid and webOS prerequisites. Explicit edition, saved profile reuse and noninteractive mode bypass the check.

User addition (0.1.4): remove the up-front private-key question. Once the TV host key is verified, use a saved/explicit identity if supplied; otherwise try passwordless root and at most three running-agent keys. Only after automatic authentication fails offer password or a key file. Save a newly chosen identity only after its authentication succeeds. Do not guess passwords or search private directories for keys. Explicit identity retains precedence. Authentication denial may advance to the next source; transport failures, partial authentication and cancellation stop the flow. Agent handles close on all exits. Noninteractive mode does not show the fallback menu.

For Paramiko 3.5.1, advance after AuthenticationException only when the auth reply event has resolved and the transport remains active and unauthenticated; timeout/EOF also use this exception class and must stop. An interrupted agent signing operation closes its connection before offering an explicit manual choice, followed by at most one fresh connection with automatic methods disabled and the same host pin verification.

User additions (0.1.5): the SHA256-copy requirement is unsuitable for ordinary users. Replace it with a first-use question showing the selected TV and trusted-home-network condition. Explicit user steering makes Enter/y the default connect-and-remember action `[Y/n]`; n/q cancels. `?` reveals technical fingerprint details, without mandatory copying. Unknown keys are never accepted noninteractively; changed saved keys remain blocked without an override. Automatically reuse exact host/port entries (including hashed names) from the user's standard OpenSSH known_hosts. A cytv pin is never overwritten by that source. Matching revoked/unsupported or malformed records stop with sanitized guidance; malformed unrelated records/comments are ignored. Only matching keys are imported, and no global SSH file is modified. This first-use approval establishes trust; it does not claim independent certification of an unknown TV.

User additions (0.1.6): installation review also defaults to yes (`[Y/n]`); removal/restore keep explicit approval. Diagnosis of the user's failed pairing found TV Active Standby plus WebSocket close 1008 with exact reason `Try Again Later (EWS)`. Classify that condition as TVNotReady during registration or read-only inventory; ask the user to turn on the TV with its remote and press Enter before retrying those reads. Noninteractive mode stops. Never retry installation/removal through this readiness loop. Pairing and inventory have separate diagnostic phases and pre-install failures state that no packages were changed by this attempt. Report only numeric close codes and allowlisted reason codes, without raw remote text. The TV is never woken or reconfigured automatically.

No-root: fetch Developer Mode key from the TV Key Server with a hidden passphrase, SSH as prisoner, pair SSAP, read inventory/icons, personalize and package on the computer, transfer and verify, install helper then launcher, configure the helper with verified atomic transfers, register EIM, launch helper. Prevent simultaneous Root routing. Report command completion separately from hardware acceptance. Developer Mode remains required; Beta renewal remains opt-in.

Root: SSH as root, verify the required TV environment, obtain fresh SSAP inventory or explicitly migrate the existing Home profile. Prepare and validate the bundle locally. Install recovery, verify its integrity, disable and stop the old Helper through its supported control command, then verify it is idle. Enable persistent Root, launch Home and verify active intent, routing and the guardian before reporting success. Offer a manual long-Home stop and retry if Helper cannot stop automatically. Keep an activation receipt on uncertain outcomes; status reconciles confirmed activation and launch, and restore returns to LG Home. No user-facing trial or Keep confirmation. Direct deployment installation remains recovery-only. Preserve recovery journals and explicit reinstallation approval. User-facing edition name: Root.

Before a mutation, atomically record a local pending operation. An interrupted/failed mutation blocks subsequent installs/removals until readback resolves it; never blindly retry. Read-only diagnosis and recovery stay accessible. No-root restore explicitly stops the helper, disables startup, removes EIM restoration and launches LG Home before uninstall. Removal verifies package absence.

Release payloads are embedded and hashed, avoiding an unsigned download/update channel. A CLI update means downloading a new executable. CLI workflows create build artifacts only and do not publish releases. Code signing/notarization is separate release work and is not claimed.

User addition: every failed step must offer the repository Issues link and an issue-ready diagnostic JSON. Generate from allowlisted installer/OS/edition/action/phase/error-type and stack locations; exclude raw exception text, local paths, addresses, credentials, app inventory, environment and TV logs. Never submit issues automatically. `doctor --report` creates the same report explicitly. An issue form requests reproduction, expected/actual results, TV model/firmware and the reviewed report.
