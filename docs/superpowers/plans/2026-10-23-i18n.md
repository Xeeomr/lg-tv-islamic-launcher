# Internationalization implementation plan

Goal: Localize the TV UI, desktop/CLI installer and user instructions in en, de, es, pt-BR, fr, it, ko, hi, pl, ru, with automatic selection and persisted manual override.

Architecture: Small offline catalogs and explicit translation calls; keep app names, protocol tokens and diagnostics intact. JS locale engine shared by both TV editions and updater. Python presentation translation preserves semantic prompt parsing. No new network requirement.

Approved specification: User accepted these ten languages and requested interface, installer, instructions, automatic selection and settings override in chat on 2026-10-23.

- [x] TV engine: write failing tests for locale normalization, preference precedence, storage failures, fallback and interpolation. Implement launcher/i18n.js, catalogs.js and i18n.css. Add remote/pointer language modal.
- [x] Launcher integration: translate static markup and dynamic messages, localize clock/date, persist language in captured profiles; update package/preview inventories.
- [x] Root/updater integration: translate settings/update/recovery dialogs, include shared engine and catalogs in both package pipelines, preserve language in Root profiles.
- [x] Installer: OS language, persisted preference, --language, GUI selector, all user-facing output and frozen resources. Test prompt semantics and locale overrides.
- [x] Documentation: localized installation, operation and recovery guides with index, links and edition-specific constraints.
- [x] Validation: locale/cross-catalog integrity tests, existing JS/Python tests, preview package integrity and browser interaction across all locales. Inspect long translations and Hindi/Korean rendering. Report hardware-only limitations.

Work takes place in stable/, preserving existing uncommitted edits. Independent installer, Root UI and docs tasks use agents per dispatching-parallel-agents; primary agent integrates launcher and verification. No releases, TV installs or commits requested.
